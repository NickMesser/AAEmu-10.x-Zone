# Managed NPC entity activity

`ZoneManagedNpcEntityActivity` owns the headless CEntity activity fields for an exact NPC generation. Entity activity, AI enablement, proxy lifetime and gameplay readiness are separate states. The script effects owner reads actual entity eligibility before accumulating `Server.OnUpdate` time. Entity timers still use their own deadline/event path while the entity is inactive or hidden.

The original 10.x call chain is:

- `CEntity` constructor `32013B30` clears active bit1 and hidden bit0x10. `ActorUnitModel::Init` `39277D00` supplies dedicated spawn flags0x200; `CActor::Init` `392E16B0` adds0x400. The managed ordinary profile starts with that applied0x600 subset and refuses the linked/update-while-hidden flag0x200000 and parented transitions. It does not implement arbitrary entity flag effects, attachment-bound update propagation, temporary activation counters or renderer state.
- Fresh NPC constructor `39345000` starts its cached active byte53 at1. After the original character constructor, `39346960` hides the dedicated entity, calls entity virtual336 withfalse, sends AIevent6, and writes byte53=0. Only afterward does it publish model flag1. The managed composite performs that order after successful authored initialization.
- Entity virtual336 resolves through `320CD998` to `3200E050`. It replaces active bit1, clears temporary activation0x3C00, then calls `3200DFB0` and `3201F7A0` to add/remove the entity from the ordinary active index. `3201FF50` copies that index for `32020480`; the latter calls entity update `32010BD0`. Hidden entities return before proxy updates unless their actual0x200000 flag allows that distinct profile.
- `CScriptProxy` virtual32 resolves through `320D78C8` to `32071E70`. It requires an actual `OnUpdate` callback and enabled `es_UpdateScript`, adds elapsed time only when called, dispatches strictly after accumulated time exceeds the selected interval, and resets the accumulator. Constructor accumulation is10seconds. Inactive/hidden frames neither advance nor reset it, so the first eligible update can run immediately.
- The existing NPC schedule runs proximity then activation every eight phase frames, including cached dead NPCs. `3933BEA0` uses actual model position and the character spatial index. `3933C020` consults the real proxy's AlwaysUpdate countdown and global `ai_UpdateAllAlways`; the original proxy starts with1024. `3933B580` hides/unhides when `gEnv.bClient==0`, then changes entity activity and sends AIevent6/7 before committing cached byte53. The prior managed `!IsDedicated` Hide gate was reversed and is corrected. The concrete world services now expose the exact adopted entity/AI/proxy and loaded float sight CVars. These two supported steps run without opening unrelated NPC gameplay gates.

No dedicated class override removes the inherited callback. Original `npc:Create` merges the actual ActorTemplate; `CreateActor` retains `BasicActor.Server.OnUpdate`. `3202B8C0` caches Server/Client callbacks through `3202A080`; default-state selector `32029180` returns class+128. `32073E20` selects the server callback on the dedicated environment. Therefore initial deactivation is a scheduling correction, not a reason to discard the original callback permanently.

Original protected callback errors are also distinct from actor retirement: script-system vtable `3557B168` virtual136 resolves to `3550C330`/`3550C2A0`, which returnsfalse after a failed protected Lua call. `32073E20` ignores that return and does not remove the actor or callback. Managed callback error classification is owned separately; unsupported host dependencies must remain explicit. Health remains the original Lua string and string/number ordering is not coerced.

Source inspection used the original DLL bytes and matching decompilations without loading engine modules. Focused controls exercise real registry-owned NPC admission, the composite initialization boundary, actual timers and proxy countdown, the eight-frame activation schedule, decimal configuration values, atomic unsupported-flag refusal and stale-generation adapters. They do not establish complete entity, renderer, CActor or gameplay parity.
